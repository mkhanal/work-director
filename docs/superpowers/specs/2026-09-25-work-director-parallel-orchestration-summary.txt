## Objective
- `work-director`: a "head of engineering" agent — taste plugin (rules that travel) + director
  (`wd` CLI orchestrating many repos), chat-first, parallel executors from **any inference provider
  driven through its command line, never its API**, on one shared branch, verify-gated merges,
  worktrees, learning loops.
- **Goals are work broken into tasks** (an epic): a goal is a runnable epic, decomposed into headed
  tasks by a planner session, spawned on one shared branch, driven to done by the coordinator.
  Complex goals run partially (`run --only`/`--heading`); simple ones run in one go (`spawn`).
- **UI is required**: goals are first-class entry points with goal-level status. In Go that is
  `wd serve` (loopback HTTP + WebSocket) and `wd tui` (terminal), both wrappers over the CLI.
- **Any outside conversation is identifiable and resumable**: `wd attach <id> <session>` binds a
  provider session started outside the director; the coordinator drives that same conversation.

## Important Details
- **The TypeScript era is over.** The source is Go: `go.mod` (module `wd`), `cmd/wd` + `cmd/taste`,
  13 packages under `internal/` (brief, cli, context, coordinator, core, ledger, open, project,
  promotion, runner, serve, taste, tui). Zero `.ts` files, no `package.json`, no lockfile.
  The gate is `go test ./...`; the plugin is generated by `go run ./cmd/taste`; the binary ships
  static via `scripts/build.sh` (CGO disabled) and installs with `scripts/install.sh`.
- **Dependencies**: `modernc.org/sqlite` (pure Go) + `golang.org/x/sys`; everything else is stdlib.
  `go vet`, `gofmt` and CI all green.
- **Command surface** (`wd <...> [--json]`): projects, add, tasks, brief, spawn, models, runner,
  epic, goal, send, attach, report, verify, decide, pr, soft-done, set, done, status, context, open,
  claim, impact, conflict, worktree, merge, concern, scan, events, feedback, distill, tui, serve,
  doctor. Every capability is a command with `--json`, so any surface (chat, script, board) is a
  thin wrapper over the same rail.
- **Requirements are the root `*.lazyspec.md`** (9 files, 115 headings), each married to
  `internal/<pkg>/<stem>_lazyspec_test.go`; `scripts/lazyspec-check.sh` proves every heading is
  married and reports no orphan test files. 10 packages carry tests; brief/core/cmd are library-only.
- **Ledger**: `work(id, project, title, kind, state, runner, session, ref, cwd, worktree, parent,
  heading, claim, impact, created, updated)`, `event`, `feedback`, `concern`, `worktree`. Additive
  migrations only — the Go wd opens a TypeScript-era ledger in place (see `docs/ledger-migration.md`).
  `EventKinds`: state, report, verify, pr, note, sent, spawn, attach, question, answer, decision.
- **Coordinator is the `/goal` drive**: briefs carry a Goal block; a coordination pass answers
  `ASK:` questions from recorded decisions, escalates unknown ones to `needs-input`, and harvests
  `STATUS: DONE|BLOCKED`. No provider `/goal` feature required.
- **Worktrees**: shared `$WD_HOME/worktrees/<project>-<kind>-<id>` on one `wd-<id>` branch per goal;
  a task may get a private worktree off the shared branch. `wd merge` is verify-gated and refuses
  while the goal's conflicts are non-empty.
- **Runner adapters**: `claude` (`--bg`, JSONL transcript), `opencode` (`run --format json`, `-s`
  resume, `session export`), `codex` (`exec --json`, `json resume`), plus any other provider as a
  spec TOML (`wd runner init`, no code change). `wd models` lists models from the provider's own CLI.
  `ao` is gone.
- **Taste**: rule cards in `taste/cards/` are the source; `go run ./cmd/taste` generates
  `plugin/` and `dist/` (31 cards → 8 skills) and CI fails if the generated tree is not committed.
