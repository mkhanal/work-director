## Objective
- Build `work-director`: a "head of engineering" agent — taste plugin (rules that travel) + director (`wd` CLI orchestrating many repos) — chat-first, parallel executors from **any inference provider driven through its command line, never its API**, on one shared branch, verify-gated merges, worktrees, learning loops.
- **Goals are epics** (user's settled framing): no separate `goal` kind; a goal *is* work broken into headed tasks; simple goals run in one go, complex ones partially (`wd epic run --only`/`--heading`), the rest left open for another conversation.
- **UI is required**: goals are first-class entry points with goal-level status; `wd ui` board lists goals and wraps every action through the real CLI.
- **Any outside conversation is identifiable and resumable**: `wd attach <id> <session>` binds a provider session started outside the director; the coordinator drives that same conversation (its own LLM) to the goal.

## Important Details
- Ground rules (AGENTS.md): TypeScript + Bun + `bun test`, zero runtime deps; director never opens project code, nothing written into managed repos except by executors as PRs; lazyspec married to tests in the same edit; `wd conflict` before spawn/merge.
- **WorkKinds = task/evolution/workflow/epic**; `isEpicLike` → `isEpic`. `wd add --kind epic` creates a goal; `wd epic plan|run|review|status|spawn` replaced the deleted `wd goal *`.
- **Coordinator is the /goal drive**: `coordinateOnce` answers `ASK:` questions from recorded decisions (resolved concerns / decision events, ≥2 significant words, containment wins), escalates unknown ones to `needs-input`, harvests `STATUS: DONE|BLOCKED`. Briefs carry a Goal block. No provider `/goal` feature needed.
- **Partial slices**: `wd epic run <id> --only <id,id>|--heading <label> [--wait]` spawns only that slice on the epic's shared worktree; leftovers stay queued for a later conversation.
- **`wd attach <id> <session> [--runner r] [--ref x] [--cwd d]`** sets runner+session+ref+cwd, records an `attach` event, and moves queued/briefed → running; `queued → running` was added to the ledger transitions, reserved for this path (spec text + married test updated).
- **`wd ui [--port n] [--open]`**: zero-dep `Bun.serve` on 127.0.0.1 (default 8787). `/` = embedded goals board (dark, vanilla JS); `/api/goals` = every epic + rolled-up per-state counts + done/total + standalone items; `/api/goal/<id>` = epic + children + rollup + events (404 on unknown/non-epic); `POST /api/action` = argv through the real CLI (default runner spawns `bun cli.ts` with same env); board's "new goal" form posts `add <project> <title> --kind epic`.
- **Free-flow gist is tracked work**: AGENTS.md chat contract — todos and the gist of a conversation land as an epic/task, never only in chat; `wd attach` identifies outside conversations.
- Editor/context (earlier turn, still shipped): `wd context` (cwd/worktree/branch + OSC-8 link), `wd open` (VS Code `code --reuse-window --goto`, `$VISUAL`/`$EDITOR` fallback). Runner-as-files engine (`wd runner list|add|init`, spec TOML) and `wd models` still live.
- Lazyspec = repo's own fact; `wd projects add` asks, "yes" files an evolution work item. Nothing committed (user hasn't asked; commit/PR available on request).
