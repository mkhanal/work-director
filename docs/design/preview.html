Web UI — preview of the consensus design

Three free models designed this independently. They converged on three surfaces, a preview-before-every-write rule, and exactly one new backend route. This page shows what that consensus looks like. It is a static mock: the real thing reads wd serve. Full reasoning in docs/design/README.md.

1 · Talk — the defining interaction

Chat-to-goal writes to a durable ledger, so nothing commits on Enter. Enter classifies; the card below is what the system understood and the exact argv it will run. Only Confirm writes. All three models independently named this the most important screen in the product.

4 · The rules the UI lives by

Rules
  1. The system shows its write before it writes. Any message that would write shows the exact argv first.
  2. Never show a command the ledger cannot verify. Unknown verbs error; they never silently no-op.
  3. Every claim names its source. Unsourced assertions render as Unconfirmed.
  4. Delivery is derived, never stored. Show the value and the git fact behind it.
  5. A finished goal is finished until someone says what is being worked on.
  6. Questions never create rows.
  7. Work state and delivery never share a pill.
  8. Live or loud. Never a blank screen; keep the last view and say it is stale.
What it must never become
  • A command palette as the whole UI — ⌘K and wd goal new is the CLI in a browser.
  • Chat that writes on send with an undo toast. Undo doesn't un-run an agent.
  • Command-palette cosplay — / verbs that are prompts rather than real CLI verbs. Power users diff against wd --help once and leave.
  • A Jira-lite board — a column per state, drag-and-drop. Dragging done→running bypasses the reopen reason and breaks the invariant.
  • Agent claims as facts — a shipped badge with no landing link is a lie you find in git.
  • Notification spam — the loop runs unattended; interrupt only for needs-input, blocked and attention.
