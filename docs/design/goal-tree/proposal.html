An inspector can get a full audit trail

Proposed sub-goals

drag to reorder · each is about one agent's work
⋮⋮1
Every record change keeps who, when, what and why
Done when a change to any form, template or setting stores its before and after, its author and a reason
Starts firstWill be planned further: touches 3 modules
⋮⋮2
An admin can export the trail for a date range
Done when the export is a signed PDF and a CSV, filtered by range, module and person
After 1One agent
⋮⋮3
The trail cannot be edited or deleted
Done when no role, API or migration can change or remove a stored entry, and a test proves it
After 1One agent
⋮⋮4
An inspector's checklist maps to the export
Done when each 21 CFR Part 11 audit-trail clause points to where the export satisfies it
After 2 and 3Research: no code
Why this breakdown

An inspector checks three things: that every change is captured, that it can be produced on demand, and that nobody can alter it. Each is its own sub-goal, so each is judged on its own.

Number 1 is large, so it will be planned into its own sub-goals when it starts, once the modules it touches are known.

Left out

Electronic signatures: they already exist and the goal doesn't ask to change them.

How you'd judge it

Exporting last month's trail for one org and handing it to an inspector with the checklist.
